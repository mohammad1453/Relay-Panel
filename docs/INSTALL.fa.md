# راهنمای نصب پنل نمایندگی Relay کنار 3X-UI

این برنامه مستقل است و باید کنار **MHSanaei/3x-ui نسخه 3.8.5** نصب شود. دیتابیس، کاربر لینوکس و سرویس جدا دارد. سرویس، تنظیمات، پورت‌ها و دیتابیس پنل اصلی در نصب و به‌روزرسانی تغییر نمی‌کنند.

**وضعیت آزمایش:** برنامه در محیط توسعه با پاسخ‌های شبیه‌سازی‌شده مطابق سورس نسخه مشخص آزمایش شده است. اتصال به پنل واقعی شما و نصب روی VPS شما هنوز انجام نشده است. پیش از استفاده تجاری، یک ورودی آزمایشی اختصاصی را بررسی کنید.

## ۱. پیش‌نیازها

Debian 12/13 یا Ubuntu 22.04/24.04/26.04 با systemd، معماری x86_64 یا aarch64، Python 3.10 یا جدیدتر، دسترسی sudo و حداقل یک گیگابایت فضای خالی. این فهرست اهداف پشتیبانی نصب‌کننده است و به معنی آزمایش واقعی روی همه این توزیع‌ها نیست.

آدرس واقعی API پنل اصلی شامل مسیر مخفی وب، توکن مدیریتی پنل یا نام کاربری و رمز آن، و محل دیتابیس اصلی را آماده کنید. اگر ورود پنل احراز هویت دومرحله‌ای دارد، از توکن مدیریتی سمت سرور استفاده کنید. توکن یا رمز پنل اصلی به مرورگر نمایندگان ارسال نمی‌شود.

قبل از نصب، فقط وضعیت را بررسی کنید:

```bash
sudo systemctl list-unit-files | grep -Ei 'x-ui|3x-ui'
sudo systemctl show x-ui.service --property=FragmentPath
sudo systemctl status x-ui.service --no-pager
sudo ss -ltnp
```

اگر سرویس نام دیگری دارد یا پنل داخل کانتینر است، تنظیمات همان نصب را بررسی کنید. مسیر دیتابیس SQLite را از تنظیمات محافظت‌شده پنل پیدا کنید؛ اگر PostgreSQL است در پرسش نصب‌کننده `external` بنویسید. فایل تنظیمات و رمزها را در فضای عمومی منتشر نکنید.

## حالت مستقیم IP و مسیر وب

برای آدرسی مانند `http://203.0.113.10:8095/relay-secret/` می‌توانید حالت سازگاری HTTP عمومی را صریحاً انتخاب کنید:

```bash
sudo bash ./install.sh --public-http \
  --origin http://IP-عمومی-VPS:8095/یک-مسیر-طولانی-و-تصادفی/ \
  --port 8095
```

آدرس باید شامل IP عمومی واقعی، همان پورت و یک مسیر وب غیرخالی باشد. در این حالت Relay روی همه رابط‌های شبکه گوش می‌دهد و نصب‌کننده فایروال را تغییر نمی‌دهد. در صورت نیاز TCP پورت 8095 را در فایروال ارائه‌دهنده یا UFW باز کنید. این حالت HTTP رمزنگاری‌شده نیست؛ مسیر مخفی جای HTTPS را نمی‌گیرد. بهتر است دسترسی فایروال را به IPهای مورد اعتماد محدود کنید یا برای دسترسی عمومی از HTTPS استفاده کنید.

## ۲. انتقال فایل و نصب

هنوز آدرس عمومی انتشار یا مخزن Git برای این پروژه وجود ندارد. با SFTP یا نرم‌افزار انتقال SSH پوشه پروژه را در `~/relay-source` روی سرور قرار دهید. پوشه‌های `.venv`، `.reference`، فایل `.env`، دیتابیس و بکاپ‌های محلی را منتقل نکنید.

روش ساده‌تر: فایل `relay-release.tar.gz` و فایل `relay-release.tar.gz.sha256` تحویلی را در پوشه خانه کاربر SSH آپلود کنید، سپس صحت فایل را بررسی و آن را استخراج کنید:

```bash
cd ~
sha256sum -c relay-release.tar.gz.sha256
mkdir -p ~/relay-source
tar -xzf relay-release.tar.gz -C ~/relay-source
```

```bash
cd ~/relay-source
sudo bash ./install.sh --dry-run
sudo bash ./install.sh
```

دستور اول فقط بررسی می‌کند و تغییری نمی‌دهد. نصب‌کننده سیستم‌عامل، معماری، سرویس‌های موجود، مسیرها، پورت‌ها و فضای دیسک را بررسی می‌کند. اگر پورت اشغال باشد توقف می‌کند؛ هیچ سرویس دیگری را متوقف نمی‌کند.

نصب‌کننده این اطلاعات را می‌پرسد: آدرس HTTPS پنل نمایندگی، آدرس کامل پنل اصلی، مسیر دیتابیس اصلی، توکن یا اطلاعات ورود پنل اصلی. رمزها هنگام تایپ نمایش داده نمی‌شوند. سپس وابستگی‌ها را نصب کرده، کاربر مستقل می‌سازد و نام کاربری و رمز مدیر اولیه را می‌پرسد. رمز را به‌خاطر بسپارید؛ رمز خام در گزارش یا فایل عمومی ذخیره نمی‌شود. ورود اول نیازمند تغییر رمز است. اجرای دوباره نصب کامل‌شده رمزها و داده‌ها را بازنشانی نمی‌کند.

مسیرهای مستقل:

| بخش | مسیر |
|---|---|
| کد برنامه | `/opt/3xui-reseller/` |
| تنظیمات و اسرار | `/etc/3xui-reseller/app.env` |
| دیتابیس برنامه | `/var/lib/3xui-reseller/app.db` |
| نسخه‌های پشتیبان | `/var/backups/3xui-reseller/` |
| سرویس | `xui-reseller.service` |

## ۳. دسترسی خصوصی با تونل SSH

اگر هنوز دامنه و HTTPS آماده ندارید، حالت خصوصی زیر را صریحاً انتخاب کنید:

```bash
cd ~/relay-source
sudo bash ./install.sh --tunnel-http --origin http://localhost:8095 --port 8095
```

روی کامپیوتر خودتان اجرا کنید و نام کاربر و آدرس VPS را جایگزین کنید:

```bash
ssh -L 8095:127.0.0.1:8095 YOUR_SSH_USER@YOUR_VPS
```

در مرورگر کامپیوتر خود `http://localhost:8095` را باز کنید. پنجره SSH باید باز بماند. اگر پورت اشغال است، پورت آزاد دیگری را در هر دو دستور انتخاب کنید. این حالت برای ارزیابی خصوصی است و نباید عمومی شود. برنامه همیشه به loopback متصل است؛ نیازی به بازکردن پورت در فایروال نیست.

## ۴. دامنه مستقل و HTTPS

دامنه اختصاصی را به IP سرور وصل کنید. اگر Nginx از قبل نصب است و گواهی معتبر دامنه را دارید، هنگام نصب بنویسید:

```bash
sudo bash ./install.sh --origin https://reseller.example.com \
  --domain reseller.example.com \
  --tls-cert /etc/letsencrypt/live/reseller.example.com/fullchain.pem \
  --tls-key /etc/letsencrypt/live/reseller.example.com/privkey.pem
```

دامنه و مسیر گواهی نمونه را جایگزین کنید. نصب‌کننده DNS، نام و انقضای گواهی و تداخل دامنه را بررسی می‌کند؛ فقط فایل جدید `/etc/nginx/conf.d/3xui-reseller.conf` می‌سازد و پس از موفقیت `nginx -t`، Nginx را reload می‌کند. تنظیمات سایت‌های دیگر و گواهی‌های موجود عوض نمی‌شوند. صدور خودکار گواهی ACME یا نصب پراکسی رقیب پشتیبانی نمی‌شود؛ از روش موجود مدیریت گواهی خود استفاده کنید.

برای Apache/Caddy یا نصب از قبل تکمیل‌شده، یک میزبان HTTPS مستقل بسازید که درخواست را با Host اصلی به `127.0.0.1:8095` بفرستد؛ سقف بدنه ۶۴ کیلوبایت و زمان پاسخ بالادست ۱۲۰ ثانیه مناسب است. برای تبدیل حالت تونل به تولید، در فایل تنظیمات `APP_ENV="production"` و `APP_ORIGIN="https://دامنه-شما"` را قرار دهید و فقط سرویس نمایندگی را restart کنید.

## ۵. اولین نماینده و مشتری آزمایشی

۱. وارد شوید و رمز اولیه را تغییر دهید. زبان فارسی از پایین نوار کناری انتخاب می‌شود.

۲. در «ورودی‌ها»، «به‌روزرسانی از پنل اصلی» را بزنید و نام، شناسه، پروتکل و پورت‌ها را بررسی کنید.

۳. نماینده جدید بسازید: نام کاربری و برچسب یکتا، رمز، حجم، انقضا و ورودی‌های مجاز را مشخص کنید. ورودی جدید خودکار مجاز نمی‌شود.

۴. با حساب نماینده وارد شوید و رمز آن را تغییر دهید. فقط روی **ورودی آزمایشی اختصاصی** مشتری کوچک بسازید. گروه بومی، حجم و تاریخ انقضا را در پنل اصلی ببینید و لینک را با کلاینت واقعی امتحان کنید.

۵. مشتری آزمایشی را حذف کنید. حجم فروخته‌شده نباید بازگردد. دفتر سهمیه و وضعیت عملیات را بررسی کنید.

انقضای طرح نماینده حساب را فقط خواندنی می‌کند؛ مشتریان موجود به دلیل انقضای نماینده قطع نمی‌شوند. حجم فروش با مصرف واقعی مشتری تفاوت دارد.

## ۶. وضعیت، گزارش‌ها و بازیابی رمز

```bash
sudo bash /opt/3xui-reseller/status.sh
sudo systemctl status xui-reseller.service --no-pager
sudo journalctl -u xui-reseller.service -n 100 --no-pager
curl --fail http://127.0.0.1:8095/healthz
cd /opt/3xui-reseller
sudo -u xui-reseller .venv/bin/python -m reseller.manage check --env /etc/3xui-reseller/app.env
sudo -u xui-reseller .venv/bin/python -m reseller.manage sync --env /etc/3xui-reseller/app.env
sudo -u xui-reseller .venv/bin/python -m reseller.manage reset-password --env /etc/3xui-reseller/app.env
```

دستور آخر نام حساب و رمز جدید را بدون نمایش می‌پرسد و نشست‌های قبلی را باطل می‌کند. برای اصلاح اتصال، `sudoedit /etc/3xui-reseller/app.env` را اجرا کنید و سپس `sudo systemctl restart xui-reseller.service`. هرگز برای این کار سرویس اصلی `x-ui.service` را restart نکنید. توکن را در آرگومان دستور یا تاریخچه شل ننویسید.

## ۷. پشتیبان‌گیری و بازیابی

```bash
sudo bash /opt/3xui-reseller/backup.sh
sudo ls -lh /var/backups/3xui-reseller/
sudo bash /opt/3xui-reseller/restore.sh --archive /var/backups/3xui-reseller/REPLACE_WITH_BACKUP.tar.gz
```

نام فایل واقعی را جایگزین کنید. بکاپ SQLite حتی هنگام اجرای برنامه سازگار است. آرشیو فقط شامل داده و تنظیمات این برنامه است و اسرار بازیابی دارد؛ نسخه رمزگذاری‌شده خارج از سرور نگه دارید. پیشنهاد نگهداری: هفت بکاپ روزانه و چهار بکاپ هفتگی. حذف بکاپ‌های قدیمی دستی است.

بازیابی به تایپ `RESTORE` نیاز دارد، هش و ساختار را بررسی می‌کند، قبل از تغییر بکاپ می‌گیرد و فقط سرویس نمایندگی را متوقف می‌کند. نشست‌ها باطل و فروش قفل می‌شود. **بکاپ این برنامه، پنل اصلی مستقل را عقب نمی‌برد.** فروش‌های بعد از زمان بکاپ را با مشتریان پنل اصلی و سابقه صورتحساب تطبیق دهید و سهمیه‌ها را اصلاح کنید. فقط پس از بررسی کامل:

```bash
cd /opt/3xui-reseller
sudo -u xui-reseller .venv/bin/python -m reseller.manage unlock-restored --env /etc/3xui-reseller/app.env
```

این دستور تأیید متنی می‌خواهد. صرف بالا آمدن سایت دلیل کافی برای بازکردن قفل فروش نیست.

## ۸. به‌روزرسانی

در محیط توسعه با `python tools/package_release.py` آرشیو انتشار و SHA-256 بسازید. آرشیو را منتقل و هش را از مسیر مورد اعتماد مقایسه کنید:

```bash
sudo bash /opt/3xui-reseller/update.sh --archive /root/relay-release.tar.gz --sha256 REPLACE_WITH_TRUSTED_64_HEX_SHA256
```

به‌روزرسان قبل از تغییر از دیتابیس و تنظیمات بکاپ می‌گیرد، فقط کد این برنامه را نصب می‌کند، مهاجرت دیتابیس و آزمون سلامت را اجرا می‌کند. در شکست، کد و داده قبلی را بازمی‌گرداند. آرشیو انتشار قبلی و بکاپ پیش از به‌روزرسانی را حفظ کنید. دیتابیس بازیابی‌شده تا بررسی مدیر قفل فروش دارد. برنامه قدیمی را روی ساختار دیتابیس جدید اجرا نکنید.

## ۹. حذف برنامه

حذف عادی، اطلاعات را نگه می‌دارد:

```bash
sudo bash /opt/3xui-reseller/uninstall.sh
```

حذف کامل و عمدی داده‌ها:

```bash
sudo bash /opt/3xui-reseller/uninstall.sh --purge-data
```

مسیرهای حذف نمایش داده می‌شود و باید `PURGE 3XUI-RESELLER` را تایپ کنید. قبل از آن بکاپ لازم را خارج سرور نگه دارید. اگر کد قبلاً حذف شده، اسکریپت موجود در پوشه سورس را اجرا کنید. دیتابیس و سرویس پنل اصلی، پراکسی‌ها، گواهی‌ها و بسته‌های مشترک حذف نمی‌شوند. فایل پراکسی اختصاصیِ بلااستفاده Relay را پس از بررسی دستی بردارید.

## ۱۰. رفع اشکال و بررسی مستقل بودن

تداخل پورت: پورت آزاد دیگری انتخاب کنید. خطای احراز هویت: توکن مدیریتی یا رمز را بررسی کنید. پاسخ HTML یا مسیر اشتباه: مسیر وب واقعی پنل را به آدرس اضافه کنید. خطای TLS: گواهی را درست کنید؛ اعتبارسنجی TLS را غیرفعال نکنید. عملیات نامعلوم: ابتدا «تطبیق امن»؛ تلاش مجدد فقط برای هویت موجود و تأییدشده ممکن است. اگر پاسخ گم شده و مشتری دیده نمی‌شود، رزرو عمداً آزاد نمی‌شود تا فروش بیش‌ازحد رخ ندهد.

```bash
sudo systemctl show x-ui.service --property=ActiveEnterTimestamp --property=FragmentPath
sudo systemctl status x-ui.service --no-pager
sudo systemctl status xui-reseller.service --no-pager
sudo stat /var/lib/3xui-reseller/app.db
```

نام سرویس، زمان شروع و هش فایل سرویس/تنظیمات پنل اصلی را قبل و بعد مقایسه کنید. دیتابیس پنل فعال به‌طور طبیعی با مصرف ترافیک تغییر می‌کند؛ ثابت‌ماندن هش دیتابیس معیار مناسبی نیست.

این دستورها را شما روی VPS اجرا می‌کنید. آزمون‌های توسعه و شبیه‌سازی نصب با نصب واقعی سرور تفاوت دارند؛ نصب روی سرور شما هنوز تأیید نشده است.
